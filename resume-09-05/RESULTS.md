## What the implementations establish

**Plain Go supplies an adequate tested baseline.** Its state machine, journal, effect service, and controller implement the entire behavior without a reused workflow package. On changed candidate bytes, it records the mismatch and performs fresh work before completing. That differs from the Warrant and Parley entries, which refuse that changed-candidate case before delivery; both behaviors meet the common requirement that old checks cannot certify changed bytes.

**Warrant supplies evidence-aware reduction; substantial recovery code remains outside it.** The new adapter handles durable loading, strict corruption refusal, incarnations, source epochs, and effect reconciliation. It bypasses the upstream runner, which starts fresh, and supplies a stricter reader than the upstream malformed-tail behavior. The interesting next question is whether another consumer becomes simpler by reusing Warrant after accounting for those responsibilities. Passing this demo does not establish that yet. [Implementation boundaries](warrant-entry/README.md), [measured footprint](warrant-entry/RUN-RESULTS.md)

**Parley adds an order diagnostic as an observer.** All three execution mutants are protocol-complete: duplicate effects, a stale incarnation, and stale candidate evidence can each accompany a legal sequence of messages. Independent execution assertions catch those failures. A separate planted ordering swap passes those effect/identity assertions but Parley identifies normalized event 2 and its raw journal record, `event-4`. That demonstrates the observer's added diagnostic in this fixture; a plain order checker remains an untested alternative to that added machinery.

Parley's Haskell compiler, projection, and observer executed. Its Python executor does not interpret the generated local contracts. Gleam enforcement was inspected by the builder but not executed; Lean was not executed. This entry demonstrates neither protocol enforcement nor a new compiler/runtime theorem.

**All three expose the same unavoidable uncertainty.** An opaque durable intent without a receipt remains unresolved even when the test controller knows the worker died before sending. The recovering worker cannot read that private ground truth. The decision is conservative because of the interface, not because the test forgot whether the effect happened.

## Scope and exact state

These are local, keyless deterministic workflows with serialized effects on one host. They test worker-process crashes, not arbitrary power loss, sink-write crashes, disk loss, multiple hosts, external API guarantees, or model reasoning. The entries document fsync/transaction assumptions and omit directory-fsync power-loss claims. Hash chains detect the tested corruption; they do not authenticate a malicious writer capable of recomputing the chain.

The same behavioral packet guided independent implementations and independently expressed local assertions. Their sample computations differ, so this is not a throughput comparison. No live Org, Gate, fleet, or production integration was exercised.
